## polish.css と diagnosis.md

修正前を書いたエージェントとは別のサブエージェントに、次の依頼文をそのまま渡して生成させた。**出力は手で整えず、そのまま置いている。**

```
次のスキルを読み、その手順に従って作業してください。

- スキル本文: (リポジトリ)/skills/design-polish/SKILL.md
- 本文が参照している references/ と assets/ は、本文が読むように指示している場合に読んでください
- Skill ツールは使わず、上のファイルを直接読んでください。このスキル以外のデザイン指針や、リポジトリ内の他の見本(docs/examples/ 配下の他のフォルダ)は見ないでください

依頼: 「このサイト(3ページ)のデザインを良くしてください。任せます。」
対象: (リポジトリ)/docs/examples/multipage/
- index.html(案件一覧)、detail.html(案件の詳細)、settings.html(設定)の3ページ。base.css と app.js を共有している
- states.html は、このサイトの部品を全状態で並べた状態一覧ページ(確認用。すでに用意してある)
- 各ページは末尾で toggle-snippet.js を読み込み、同じフォルダの polish.css を共通層のCSSとしてオン・オフする(polish.css はまだ存在しない)

出力:
1. 共通層のCSSを、同じフォルダに polish.css として保存する。既存のCSS(base.css と各ページ内の <style>)の後に読み込まれる上書きCSSとして書く。外部の読み込みは禁止
2. 診断(棚卸し、判定、方向性、対応表)、ページ固有の変更一覧、手順8の報告を、同じフォルダに diagnosis.md として保存する

制約: 既存のファイル(3ページのHTML、states.html、base.css、app.js、toggle-snippet.js)は編集しない。この見本では、CSSの切り替えだけで前後を比べるため、マークアップや文言の変更(ページ固有層)は適用せず、変更一覧として diagnosis.md に書くにとどめる。

ユーザーは不在です。確認は取らずに最後まで進めてください。前後比較ページは作らなくて構いません。

最後に、次の2点を報告してください。
- 行った検証(コントラスト比は計算した値を書く)
- SKILL.md と references の文面だけでは判断に迷った箇所、足りなかった箇所、うまく従えなかった箇所(なければ「なし」)
```

依頼文中の「(リポジトリ)」は、実際には作業環境の絶対パス。

## この見本で見られるもの・見られないもの

- 見られる:共通層(色・文字・余白の体系と部品の見た目)の前後。CSSだけの切り替えなので、絵文字つきの見出しや文言は修正前のまま残る
- 見られない:ページ固有層(構成、主役、文言)の変更。`diagnosis.md` の変更一覧に、提案として書かれている
