# 複数ページの進め方(詳細)

SKILL.md の「複数ページの進め方」の詳細。対象が2ページ以上のときに読む。

## 1. 2層に分ける理由

複数ページのサイトで質感が揃わない原因は、たいてい共通の体系がないこと。ページごとに直すと、直した人の判断がページの数だけ増え、ばらつきが残る。

| 層 | 含むもの | 変更の届き方 |
|---|---|---|
| サイト共通層 | 色・文字・余白・角丸・影の体系、部品(ボタン、入力欄、カード、表、ナビ、バッジ、モーダル)の見た目、ページの枠組み(最大幅、ヘッダー、見出しの段階) | CSSだけで全ページに届く |
| ページ固有層 | そのページの構成(情報の順序、まとまり)、主役、文言 | ページごとにマークアップや文言を触る |

迷ったら「2ページ以上に出てくるか」で分ける。出てくるなら共通層。

境目にあるものの扱いは次のとおり。

- **1ページにしかないが、CSSだけで直せる部品**(そのページだけの進捗バー、絞り込み欄など):共通層のCSSに入れる。ただし「ページ単位の値の置き換え」として節を分け、体系の値に置き換えるだけにする。入れないと、共通層を当てた後もそのページだけ古い見た目が残る
- **CSSだけで直せる構成の問題**(同格の主ボタンが2つ、など):どれを主役にするかはページの判断なので、ページ固有層に回す
- **役割が同じでクラス名が違う部品**:共通層のCSSではセレクタを並べて同じ見た目にする。クラスの統合はマークアップの変更なので、変更一覧に回す

先に共通層を仕上げる。共通層が決まると、ページ固有の問題のうち半分ほどは消える(見出しの差、余白の不揃い、ボタンの格など)。残ったものがページ固有層の仕事になる。

## 2. 代表ページの選び方

**型**の違うページを3〜5枚選ぶ。型とは、画面の役割と骨格の組み合わせのこと。

- 一覧(表、カードの並び)
- 詳細(1件の情報、タブ、操作ボタン)
- フォーム(入力、設定)
- トップ・ダッシュボード(要約、導線)
- 文章中心(ヘルプ、規約、記事)

選ぶ基準は次のとおり。

- 利用頻度の高いページを優先する
- 部品の種類が多いページを1枚は入れる(棚卸しの材料になる)
- 同じ型は1枚でよい。商品Aの詳細と商品Bの詳細を両方読む必要はない
- モーダルやタブなど、動的な部品を含むページを1枚は入れる

選んだページと、選ばなかった型があればそれも診断に書く(「記事ページは未確認」など)。

## 3. 値の棚卸し

「なんとなく揃っていない」を数で示すための作業。対象は次の5種類。

- 色(文字色、背景色、罫線色)
- 文字サイズと太さ
- 余白(padding、margin、gap)
- 角丸
- 影

### コードがある場合

スクリプトを実行できる環境なら、`scripts/inventory.py` にCSSファイルとページのHTMLを渡すと、下の数え方で集計した表が出る。

```
python3 scripts/inventory.py base.css index.html detail.html settings.html
```

「直書きのうち1〜2か所だけ」の列が、その場で書かれた値の多さを表す。実行できない環境では、次のように読んで数える。

スタイルの定義元(CSSファイル、Tailwindの設定、テーマ)を読み、値を拾って数える。Tailwindならクラスの出現(`text-sm`、`p-4`、`rounded-xl`、任意値の `p-[13px]` など)を数えるのが早い。任意値(角括弧つき)の多さは、体系から外れた箇所の多さを表す。

### 描画後のDOMから数える場合

ユーザーに、対象ページを開いてブラウザのコンソールに次を貼ってもらう。読み取るだけで、ページは変更しない。外部への通信もしない。

```js
(() => {
  const tally = { color: {}, background: {}, border: {}, fontSize: {}, fontWeight: {}, space: {}, radius: {}, shadow: {} };
  const add = (k, v) => { if (v) tally[k][v] = (tally[k][v] || 0) + 1; };
  const zero = v => !v || v === '0px' || v === 'none' || v === 'normal' || v === 'auto';
  for (const el of document.querySelectorAll('body *')) {
    if (el.closest('script,style,svg') && el.tagName !== 'svg') continue;
    const s = getComputedStyle(el);
    if (s.display === 'none') continue;
    const hasText = [...el.childNodes].some(n => n.nodeType === 3 && n.textContent.trim());
    if (hasText) { add('color', s.color); add('fontSize', s.fontSize); add('fontWeight', s.fontWeight); }
    if (s.backgroundColor !== 'rgba(0, 0, 0, 0)') add('background', s.backgroundColor);
    if (parseFloat(s.borderTopWidth) > 0) add('border', s.borderTopColor);
    for (const p of ['paddingTop', 'paddingLeft', 'marginTop', 'marginBottom', 'rowGap', 'columnGap']) if (!zero(s[p])) add('space', s[p]);
    if (!zero(s.borderTopLeftRadius)) add('radius', s.borderTopLeftRadius);
    if (!zero(s.boxShadow)) add('shadow', s.boxShadow);
  }
  const out = {};
  for (const k in tally) out[k] = Object.entries(tally[k]).sort((a, b) => b[1] - a[1]).map(([v, n]) => `${v} ×${n}`);
  console.log(JSON.stringify(out, null, 2));
  return out;
})();
```

代表ページそれぞれで実行し、結果を貼ってもらう。自分でページのHTML/CSSを取得できる場合は、CSSの宣言を読んで同じ集計をする。

### 数え方

人によって数が変わらないよう、次のように数える。

- 色は表記の違いで数える(`#666` と `#666666` は同じ、透明度が違えば別)。グラデーションと影の中の色は、色の種類には含めず「グラデーション ○か所」「影 ○種類」として別に数える
- ページ内の `<style>` や `style` 属性に書かれた値も含める

### 読み方

- **種類の数**を見る。灰色が10種類以上、文字サイズが8種類以上、余白が15種類以上あれば、体系がないと判断してよい
- **出現数の少ない値**を見る。1〜2回しか使われていない値は、その場で書かれた値であることが多い
- **近い値のかたまり**を見る。`13px, 14px, 15px` や `#666, #6b7280, #707070` は、1つに寄せられる
- 多く使われている値は、新しい体系でも残す候補になる。既存の決定を尊重する

## 4. 部品の棚卸し

複数のページに繰り返し現れる部品を特定し、見た目のばらつきを記録する。

| 部品 | 現れるページ | ばらつき |
|---|---|---|
| 主ボタン | 一覧、詳細、設定 | 高さ 36/40/44px、角丸 6/8/999px、色 3種 |
| 入力欄 | 設定、詳細(モーダル内) | 枠線色 2種、フォーカス表示なし |
| カード | 一覧、詳細 | 影 3種、余白 16/20/24px |

見るのは次の点。

- 同じ役割なのに見た目が違うもの(統一の対象)
- 違う役割なのに見た目が同じもの(主ボタンと副ボタンの区別がない、など)
- 状態が欠けているもの(ホバー、フォーカス、無効、エラー)

部品の特定は、クラス名だけに頼らない。クラス名が違っても役割が同じなら同じ部品として数える。

## 5. 対応表

棚卸しの結果から、古い値を新しい体系のどれに寄せるかを決める。これが共通層の設計図になる。

```
文字サイズ(11種類 → 6段階)
  11px, 12px        → 12px  (注記)
  13px, 14px, 15px  → 14px  (本文・小)
  16px, 17px        → 16px  (本文)
  18px, 20px        → 20px  (小見出し)
  24px, 26px        → 24px  (見出し)
  32px, 36px        → 32px  (ページ見出し)

灰色(9種類 → 4役割)
  #111, #1f2937, #222      → --text        本文
  #555, #666, #6b7280      → --text-muted  補助文
  #ccc, #d1d5db, #e5e7eb   → --border      罫線
  #f5f5f5, #f9fafb         → --surface     面
```

- 寄せ先は、既存で最も多く使われている値か、それに近い段階を選ぶ
- ブランドカラーなど、根拠のある既存の決定は動かさない
- 寄せ先がない値(1か所だけの特殊な値)は、本当に特殊な理由があるかを確かめ、なければ最寄りの段階に寄せる

## 6. 診断の出力形式

複数ページのときは、冒頭に棚卸しを置き、判定を層ごとに書く。

## 7. 成果物の形式

### 共通層のCSS

1ファイルにまとめる。構成は次の順にする。

1. トークン(`:root` のカスタムプロパティ):色、文字、余白、角丸、影
2. 土台:`body`、見出し、リンク、フォーカス表示
3. 部品:ボタン、入力欄、カード、表、ナビ、バッジ、モーダルなど。各部品に状態(ホバー、フォーカス、無効、エラー)を含める
4. `prefers-reduced-motion` などの環境への対応

上書きCSSとして渡す場合(確認用、またはコードがない場合)は、次に気をつける。

- 既存の定義より後に読み込まれる前提で書く。詳細度の競争になる箇所は、`!important` を乱発する前にセレクタを見直す。どうしても必要な箇所だけに使い、使った箇所を報告する
- 既存のCSSがグラデーションや影を `background` / `box-shadow` で指定している場合、色だけ変えても残る。`background-image: none` などで打ち消す
- 冒頭のコメントに、対応表の要約と、どの部品をどのセレクタで狙っているかを書く
- スクリプトが付け外しするクラス(`.is-open`、`.active`、`.hidden` など)の表示・非表示の仕組みを壊さない。`display` を上書きするときは特に確かめる
- ページ側がより強いセレクタで部品を上書きしている場合は、同じ強さのセレクタを共通層のCSSに書いて打ち消してよい(確認用の上書きとして)。本番ではページ側の上書きを消す。どこを打ち消したかを冒頭のコメントに書く
- `style` 属性に直接書かれた値は、上書きCSSからは届かない。無理に打ち消さず、変更一覧に回す
- 状態一覧で「未実装」になっている状態(読み込み中など)は、マークアップに手がかりがなければ先回りして作らない。報告に書く

### ページ固有の変更一覧

ページごとに、何を・なぜ・どう変えるかを書く。マークアップの変更を伴うものはここに入る。

```
## 設定ページ
1. 保存ボタンを1つにする(構成)
   今:各セクションの末尾に「保存」が3つ。どれも主ボタン
   変更:ページ末尾の1つを主ボタンにし、セクション内のものは削除を提案。削除できない場合は副ボタンの見た目に
   機能への影響:ボタンの削除はフォームの送信経路を変えるため、要確認
2. 見出し「⚙️ 設定をカスタマイズしよう!」→「設定」(文言)
```

機能に影響しうる変更(操作要素の削除や統合)は、勝手に行わず「要確認」として分ける。

## 8. 運用中サイトを読むとき

- 読み込みは**1ページにつき1回**。取得したHTML/CSSを手元に置いて読み返し、同じページを繰り返し取得しない
- 読むのは代表ページの3〜5枚だけ。リンクをたどって全ページを巡回しない
- ログインが必要なページ、フォームの送信、状態を変える操作は行わない。必要ならユーザーにスクリーンショットや棚卸しスクリプトの結果を頼む
- 取得できなかったページは、推測で診断せず「未確認」と書く
