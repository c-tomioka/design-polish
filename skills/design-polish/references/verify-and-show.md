# 動的な表示の確認と、結果の見せ方(詳細)

SKILL.md の「動的な表示の確認」「結果の見せ方」の詳細。同梱ファイルの使い方をまとめる。

## 目次

1. 同梱ファイルの一覧

## 1. 同梱ファイルの一覧

| ファイル | 用途 |
|---|---|
| `assets/toggle-snippet.js` | 共通層のCSSを同じ画面上でオン・オフする。開発環境のページに貼る |
| `assets/bookmarklet-builder.html` | CSSを貼るとブックマークレットを作るページ。手を入れられないサイトで使う |
| `assets/state-gallery-template.html` | 部品を全状態で並べる状態一覧ページのひな形 |
| `assets/compare-template.html` | 修正前後のHTMLを埋め込む前後比較ページのひな形 |
| `assets/example-compare.html` | 比較ページの実例(告知ページ)。見本を求められたときに見せる |
| `scripts/build_compare.py` | 比較ひな形に修正前後のHTMLを埋め込む。実行できる環境で使う |
| `scripts/check_external.py` | 外部からの読み込みがないかを調べる |

どれも外部の読み込みがない静的なファイルで、ビルドは要らない。

## 2. 切り替えスニペット(開発環境に貼る版)

ページを再読み込みせずに、共通層のCSSだけを付けたり外したりする。モーダルを開いたまま、タブを切り替えたまま、エラーを表示したまま前後を比べられるのが利点。

### 使い方

確認したいページの `</body>` の直前に、次のどちらかを入れる。

```html
<!-- CSSファイルを指定する場合 -->
<script src="toggle-snippet.js" data-polish-href="polish.css"></script>

<!-- CSSを直接書く場合 -->
<script src="toggle-snippet.js" data-polish-css="body{background:#fafaf8}"></script>
```

`src` で読めない環境では、`toggle-snippet.js` の中身を `<script>` に貼り、冒頭の `CONFIG` に `href` か `css` を書く。

- 画面の右下に切り替えボタンが出る。押すとオン・オフが入れ替わる
- キーボードでは `Alt + P`
- 状態はブラウザに保存され、同じサイトの別ページへ移っても引き継がれる。複数ページを行き来しながら確認できる
- ボタン自体は対象ページのCSSの影響を受けない(Shadow DOM の中に描く)

### できないこと

- 入れ替えられるのはCSSだけ。マークアップや文言の変更(ページ固有層の多く)は切り替わらない。それらは前後比較ページで見せる
- コンポーネントの中のクラスを書き換えた修正(Tailwind のユーティリティの変更など)も切り替わらない。「前後比較ページ」の「ビルドが必要な構成のとき」に従う
- 確認が済んだら、スニペットは本番のコードから外す。上書きCSSも本番に入れず、値の定義元(設定ファイル、共通部品)を直す

## 3. ブックマークレット版

コードに手を入れられないサイト(運用中のサイト、他チームの環境)で、同じ切り替えをブックマークから行う。

1. `assets/bookmarklet-builder.html` をブラウザで開く
2. 共通層のCSSを貼る
3. 出てきたリンクをブックマークバーにドラッグする(またはコードをコピーして、ブックマークのURL欄に貼る)
4. 対象のページを開き、ブックマークを押すたびにオン・オフが入れ替わる

注意点。

- CSSはブックマークレットの中に埋め込まれる。外部からは何も読み込まない
- ページを移動すると外れる。移動先でもう一度押す
- サイトの設定(コンテンツセキュリティポリシー)によっては、スタイルの挿入が拒否されて動かないことがある。その場合は開発者ツールでCSSを貼るか、スクリーンショットでの確認に切り替える
- 見た目を自分のブラウザの中で変えるだけで、サイト自体には何も送らない

## 4. 状態一覧ページ

部品を、取りうる状態すべてで1ページに並べたもの。操作して状態を作らなくても、次のことが一目で分かる。

- 状態が抜けている部品(フォーカス表示がない、無効の見た目がない)
- 部品どうしで揃っていない箇所(ボタンと入力欄の高さ、角丸、フォーカスの色)
- 共通層のCSSを変えたときの影響範囲

### 並べる状態

| 状態 | 作り方 |
|---|---|
| 通常 | そのまま置く |
| ホバー | 実際のホバーは保持できないので、`.is-hover` などの確認用クラスを付け、共通層のCSSで `:hover` と同じ宣言を当てる(`.btn:hover, .btn.is-hover { … }`) |
| フォーカス | 同様に `.is-focus` を `:focus-visible` と並べて定義する |
| 無効 | `disabled` 属性、または `aria-disabled="true"` |
| 読み込み中 | `aria-busy="true"` や、そのサイトが使っている読み込み中の表現 |
| 空 | データが0件のときの表示(表、一覧、検索結果) |
| エラー | `aria-invalid="true"` とエラー文。フォーム全体のエラー表示も |

部品によって当てはまらない状態は省く(表に「フォーカス」はない、など)。当てはまるのに未実装の状態は、空欄にせず「未実装」と書いた枠を置く。それが診断の材料になる。

### 作り方

1. `assets/state-gallery-template.html` を複製する
2. 対象サイトのCSSを読み込む(ひな形の指定箇所に `<link>` か `<style>` を入れる)
3. 部品の棚卸しで見つけた部品を、**実際のマークアップのまま**貼る。クラス名や入れ子を変えると、確認の意味がなくなる
4. モーダルやドロップダウンなど重ねて表示する部品は、開いた状態を枠の中に静的に置く(`position: fixed` を枠内に収めるための指定がひな形にある)
5. 切り替えスニペットを入れておくと、状態一覧の上で前後を比べられる

確認用クラス(`.is-hover`、`.is-focus`)を共通層のCSSに足す場合、それは確認のためだけの宣言なので、本番に入れるかどうかはユーザーに任せる。

## 5. 前後比較ページ

修正前と修正後のHTMLを1ファイルに埋め込み、同じ位置で切り替えて見せるページ。成果を見せるときの基本の形。

### なぜ1ファイルか

会話の中で表示する場合も、ファイルとして保存してローカルで開く場合も、同じものがそのまま動くようにするため。別ファイルを参照する形にすると、表示する場所によって読み込めなくなる。

### 作り方(スクリプトを実行できる場合)

```
python3 scripts/build_compare.py --before before.html --after after.html -o compare.html \
    --title "画面の名前" --verdict 改修 --note "ひとことの説明"
```

`</script` と `<!--` の書き換え、題名や判定の記入まで行う。埋め込む前に `scripts/check_external.py before.html after.html` で、外部の読み込みが残っていないかを確かめておく。

### 作り方(手で埋め込む場合)

1. `assets/compare-template.html` を複製する
2. 修正前のHTML全体を `<script type="text/plain" id="dp-before">` の中に、修正後を `id="dp-after"` の中に貼る
3. 貼るHTMLの中の `</script` を、すべて `<\/script` に書き換える(そのままだと埋め込みがそこで途切れる)。同様に `<!--` は `<\!--` に書き換える。表示するときに元へ戻される
4. 冒頭の `DP_META` に、題名と判定、ひとことの説明を書く
5. 開いて、切り替えと表示幅の変更が動くことを確かめる

### 埋め込むHTMLの条件

- 単体で開けること。CSSとスクリプトはインラインにする
- 外部の読み込み(CDN、Webフォント、画像のURL)がないこと。あると、見せる場所によって崩れる。元の画面が外部の画像を使っている場合は、同じ大きさの枠に置き換えて、その旨を書く
- 修正前のHTMLは、編集を始める前に控えたものを使う

### ビルドが必要な構成のとき

React、Vue、Svelte などで単体のHTMLにできない場合は、比較ページを必須にしない。修正の入り方で見せ方を選ぶ。

| 修正の入り方 | 見せ方 |
|---|---|
| 1枚のCSS(トークン、共通のスタイルシート)で表せる | 切り替えスニペットを開発環境に入れて見てもらう |
| コンポーネントの中のクラスやマークアップを書き換えた(Tailwind のユーティリティの変更など) | 実際の差分と、開発サーバーで前後を見比べる手順を渡す |
| 描画後のHTMLとCSSを保存できる手段がある | それを埋め込んで比較ページにする(スクリプトの動作は再現されないと明記する) |

開発サーバーで見比べる手順は、修正前を git の直前の状態から出す形で書く。

- コミット前:変更を一時的に退避すれば修正前、戻せば修正後が表示される
- 前後を並べて見たい:修正前のコミットを別の作業ツリーに出し、別のポートで開発サーバーを立てる

どちらもユーザーの作業ツリーを動かす操作なので、手順として渡し、勝手には行わない。

比較ページのために、画面を静的なHTMLとして手で書き起こさない。実際の描画と一致する保証がなく、見せたものと直したものが別物になる。どの方法で見せたかと、表示して確かめられなかった点は報告に書く。

### 見本

`assets/example-compare.html` が、このひな形に実際の修正前後を埋め込んだもの。ユーザーが「どう変わるのか先に見たい」と言ったときは、これを表示する。自分で比較ページを作るときの手本にもなる。

## 6. どれを使うか

| 場面 | 使うもの |
|---|---|
| 1画面を直した結果を見せる | 前後比較ページ |
| 共通層のCSSを、開発中のサイトで確かめる | 切り替えスニペット |
| 共通層のCSSを、手を入れられないサイトで確かめる | ブックマークレット |
| モーダル・タブ・エラーなどを保ったまま前後を比べる | 切り替えスニペット(またはブックマークレット) |
| 部品の状態の抜けと不揃いを確かめる | 状態一覧ページ |
| 構成や文言の変更(マークアップが変わる)を見せる | 前後比較ページ |
| ビルドが必要な構成で、コンポーネントを書き換えた | 差分と、開発サーバーで見比べる手順 |
| スキルの効果を先に見たいと言われた | `assets/example-compare.html` |
